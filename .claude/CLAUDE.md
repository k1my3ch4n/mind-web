## 프로젝트 개요

mind-web은 마인드맵 형태로 웹 페이지의 구조를 설계하고, 그 구조를 바탕으로 실제 동작하는 웹 페이지를 미리 확인해볼 수 있는 프로덕트입니다.

- 마인드맵의 노드는 하나의 웹 페이지를 의미하며, 노드 간 연결은 페이지 간 이동 경로(라우트)를 의미합니다.
- 각 노드(페이지)의 세부 화면에서 해당 페이지의 기본적인 레이아웃을 디자인하고 수정할 수 있습니다.
- 버튼, 모달 등 자주 쓰이는 기본 컴포넌트를 제공하여, 레이아웃을 넘어 프로토타입 수준의 간단한 웹 페이지까지 구성할 수 있습니다.
- 완성된 마인드맵 구조를 기반으로 간단한 웹 페이지를 생성하여 실제 동작을 확인할 수 있습니다.

## 프로젝트 목표

- 새로운 프로젝트나 패키지를 시작하기 전에, 페이지 구조와 라우팅 흐름을 마인드맵으로 빠르게 설계하고 시각화한다.
- 마인드맵 상에서 각 페이지의 레이아웃을 바로 수정하며 구체화할 수 있게 한다.
- 기본 레이아웃뿐 아니라 버튼·모달 같은 기본 컴포넌트를 제공하여, 별도 개발 없이도 동작하는 프로토타입 수준의 웹 페이지를 빠르게 만들 수 있게 한다.
- 설계한 마인드맵을 실제 웹 페이지 형태로 미리 확인하여, 레이아웃과 구조를 사전에 점검하고 팀원과 논의·합의할 수 있는 환경을 제공한다.

## 제품 포지셔닝 / 차별화 포인트

유사 카테고리 도구(Whimsical, FigJam, Framer, Excalidraw 등)와 비교했을 때 mind-web이 지켜야 할 차별점.

- **"그림"이 아니라 "구조 그 자체"**: 기존 다이어그램/화이트보드 도구에서 박스를 그리고 선으로 잇는 것은 시각적 표현(그림)에 불과하다. mind-web은 노드=페이지, 엣지=라우트로 1:1 매핑되므로, 그린 다이어그램 자체가 곧 사이트의 정보구조(IA)이자 프리뷰를 만들어내는 데이터여야 한다.
- **다이어그램 ↔ 실제 결과물의 자동 동기화**: 와이어프레임 도구(Whimsical)는 "그렇게 생긴 화면을 그린 그림"에 머물고, 페이지 빌더(Framer)는 실제로 동작하지만 사이트 구조 자체가 메인 캔버스는 아니다. "구조를 그리면 곧 클릭 가능한 프로토타입이 된다"는 지점이 핵심 차별점이며, 설계와 결과물 사이에 변환·동기화 비용이 없어야 한다.
- **설계 초기 단계에 최적화된 "가볍지만 동작하는" 포지션**: Figma/Framer는 비주얼 디자인이 어느 정도 갖춰진 후 진가를 발휘하고, 와이어프레임 도구는 빠르지만 눌러볼 수 없는 그림에 머문다. mind-web은 그 중간 — 구조와 흐름을 빠르게 잡으면서 실제로 눌러보고 흐름을 검증할 수 있는 지점을 노린다.

### 개발 시 유의할 트레이드오프

"그리는 속도(마인드맵의 가벼움)"와 "실제로 동작하는 정확도(프리뷰의 신뢰감)" 사이에서 계속 균형을 잡아야 한다. 너무 정교해지면 Framer처럼 무거워지고, 너무 단순해지면 기존 와이어프레임 도구와 다를 게 없어진다. **"팀이 개발 착수 전에 구조·흐름에 합의하는 도구"**라는 타겟에 집중하면 이 균형을 잡기 쉬워진다.

## 향후 확장 아이디어

- 완성한 프로토타입을 실제로 호스팅하여 외부에 공유하는 기능 (우선순위는 낮음, 프로토타입 단계 이후에 검토)

### AI 활용 방향

워크플로우 단계별로 아래와 같은 적용 지점을 검토 중.

- **구조 설계(마인드맵)**: 자연어 설명 → 마인드맵(페이지 구조·라우트) 초안 자동 생성 · 누락된 페이지/라우트 제안 · 서비스 유형별 표준 구조 템플릿 추천
- **레이아웃·컴포넌트**: 페이지 목적(로그인, 대시보드 등)에 맞는 레이아웃·컴포넌트 배치 추천 · 자연어 명령으로 컴포넌트 배치(예: "여기에 로그인 폼 넣어줘") · 기존 페이지와의 디자인 일관성 체크
- **콘텐츠**: 페이지 내 더미 콘텐츠(텍스트, 카피 등) 자동 채우기 · 톤앤매너에 맞는 카피 제안
- **검토·협업**: 구조를 분석해 IA 문제(순환 참조, 고립 노드, 과도한 depth 등) 탐지 및 UX 흐름 피드백 제공 · 팀 논의용 구조 요약·문서 자동 생성

mind-web의 마인드맵은 노드=페이지·엣지=라우트로 매핑되는 구조화된 데이터이기 때문에, 그림 기반 도구(Whimsical, FigJam 등)는 할 수 없는 그래프 구조 분석·시뮬레이션 기반 피드백이 가능하다. 이는 위 "제품 포지셔닝 / 차별화 포인트"와 직접 연결되는 AI 방향이다.

**우선순위**: "자연어 → 마인드맵 생성" 같은 큰 기능보다, 리스크가 낮고 구조화된 데이터를 바로 활용할 수 있는 "구조 분석 기반 피드백"이나 "더미 콘텐츠 채우기"부터 시작하는 것을 권장.
